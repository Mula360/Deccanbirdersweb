# PITTA search index

The Archives page searches the full text of every PITTA edition. Three pieces make that work:

| Piece | What it is |
|---|---|
| `data/pitta-catalog.csv` | Every edition: `year, month, edition, drive_id, status, notes`. `edition` is `Regular` or `Special - <name>`. `status` is `IN DRIVE` or `MISSING`. |
| `data/pitta-index.json` | Per-page text of every edition. It is generated by `build_index.py`, so don't edit it by hand. |
| `assets/pitta-covers/{key}.jpg` | The cover shown on the Archives page: page 1 of each PDF, generated by `build_covers.py`. |
| **PITTA Archive → Sync from catalog** (wp-admin) | Creates or updates one PITTA issue per catalog row. Only editions with a published issue show up in search. |

An edition's key is `{year}-{mm}-{slug(edition)}`, e.g. `2015-11-special-talakona`. The script's `catalog_key()` and `db_pitta_catalog_key()` in `functions.php` must agree on it.

## Adding a new issue

1. Upload the PDF to the year's PITTA folder on Google Drive. The folder must be shared as *Anyone with the link → Viewer*.
2. Add a row to `data/pitta-catalog.csv`, e.g. `2026,9,Regular,<drive file id>,IN DRIVE,`. The file id is the part between `/file/d/` and `/view` in the share link.
3. Run both scripts. They only fetch files they haven't cached before:
   ```sh
   python3 tools/pitta-index/build_index.py
   python3 tools/pitta-index/build_covers.py
   ```
4. Commit `data/pitta-catalog.csv`, `data/pitta-index.json` and the new cover in
   `assets/pitta-covers/`, then deploy the theme.
5. In wp-admin, go to **PITTA Archive → Sync from catalog → Run sync**.

## Notes

- **Requirements:** poppler (`pdftotext`, `pdftoppm`) is required. `tesseract` is optional. Install with `brew install poppler tesseract`. Scanned pages with no text layer are OCR'd only when tesseract is installed. The script lists editions whose text came out mostly empty.
- **Downloads:** PDFs are cached in `tools/pitta-index/.cache/`, which is gitignored. Use `--refresh` to download again after replacing a file in Drive.
- **Rebuilding one edition:** `--only 2026-09-regular` works on both scripts; the index merges it into the existing file, and `build_covers.py --refresh` re-renders covers that already exist.
- **Local PDFs:** `--pdf-dir DIR` reads `DIR/{key}.pdf` instead of downloading from Drive.
- **MISSING rows:** these are skipped everywhere. When a missing issue turns up, fill in `drive_id`, set `status` to `IN DRIVE` and follow the steps above.
